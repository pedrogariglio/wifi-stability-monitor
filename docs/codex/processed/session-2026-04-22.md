# Sesión Codex - 2026-04-22

##Problema
Revisión de configuración de Prometheus y Docker Compose en el proyecto para asegurar el correcto monitoreo de node-exporter.

---

##Contexto
- Proyecto con Docker Compose (v2)
- Prometheus configurado mediante `prometheus.yml`
- Uso de red Docker custom: `monitor-net`
- Node exporter expuesto en el host

---

##Problemas detectados

1. Uso de `version: '3.9'` en `docker-compose.yml`
2. Configuración de target en Prometheus usando IP fija (`172.x.x.x`)
3. Posible estado `DOWN` en el target de `node-exporter`
4. Uso de `latest` en imágenes Docker
5. Exposición de variables sensibles al usar `docker compose config`

---

##Diagnóstico

- Docker Compose v2 ya no requiere el campo `version`
- La IP `172.17.0.1` corresponde al bridge por defecto, no a redes custom
- En redes como `monitor-net`, la gateway puede cambiar
- Prometheus no logra alcanzar el exporter si la IP es incorrecta
- `docker compose config` expone variables del `.env` en texto plano

---

##Solución

### 1. Docker Compose
- Se elimina `version: '3.9'`
- Se evita el uso de `latest` → se fijan versiones específicas

### 2. Conectividad hacia el host
En `prometheus.yml`:

targets: ["host.docker.internal:9100"]
